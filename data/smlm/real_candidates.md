# Real SMLM recordings with a known geometry: survey of candidates (2026-11-09)

Purpose: find REAL single-molecule localization recordings (raw camera frames, not only localization tables) with a known ground-truth geometry, on which the sliding inverse scale space (ISS) can be tested against Picasso (and ThunderSTORM where possible) in a pre-registered run (`results/smlm/real_gt_plan.md`). Surveyed by one agent on 2026-11-09 (UTC, about 07:00 to 07:55). Raw data are never committed: they live in `/home/user/smlm_real_data/` and are re-fetched by `data/smlm/fetch_real_gt.py` (digests in `data/smlm/checksums_real_gt.json`). Numbers marked (U) come from `experiments/real_gt_usability_check.py` (output `results/smlm/real_gt_usability.json`); they are facts about the files, not scores of any localizer.

## Summary

**No raw-frame dataset of a DNA-origami grid or Picasso origami test sample with designed 20 / 40 / 80 nm spacings and several fields of view was reachable.** The only designed-spacing origami raw frames found are the SIMFLUX 80 nm DNA-PAINT nanorulers (rank 3: patterned illumination, no pixel size or calibration in the files, ruler design not documented beyond the title). The Zenodo records of the Jungmann lab (RESI, SUM-PAINT, dye analysis, labeling efficiency, SPINNA, L-DNA-PAINT, SporPAINT, Glyco-RESI, ...) publish **localization tables** (hdf5), not camera frames. The Raab et al. nanoruler record (the traceable nanoruler distances) was downloaded and rejected: it holds localization lists and pixel-size calibration images, no raw nanoruler movies.

**What is available is nuclear pore complexes (NPC)**, which are the in-situ reference standard the task also allows:

## Hosts and queries

* **Zenodo** (`https://zenodo.org/api/records?q=...`, page size 25 is the anonymous maximum): about 35 queries (up to 3 pages each): "DNA-PAINT origami", "DNA origami SMLM raw data", "nanoruler", "Picasso origami", "Nup96 nuclear pore SMLM", "SMLM benchmark raw tiff", "DECODE experimental", "STORM calibration structure", "DNA-PAINT raw movie", "GATTA-PAINT", "origami grid DNA-PAINT", "20 nm grid DNA-PAINT", "Nup96", "Nup107 SNAP", "nuclear pore complex localization microscopy raw frames", "ShareLoc", "single-molecule localization microscopy raw data tif", "DNA-PAINT nanoruler raw data", "DNA origami super-resolution ground truth", "SMLM raw image stack ground truth", "localization microscopy benchmark experimental", "Picasso localize test data", "RESI", "dSTORM DNA origami", "STORM raw data nuclear pore", "DNA-PAINT 3D origami", "SMLM challenge experimental", "DNA-PAINT", "Jungmann", "ThunderSTORM", "dSTORM raw data", "SMLM dataset", "Picasso DNA-PAINT". About 600 distinct records were listed; the plausible ones were opened (file lists, sizes, md5, descriptions).
* **EMPIAR** (EBI search `ebisearch/ws/rest/empiar`): the queries "SMLM", "single molecule localization", "DNA-PAINT" TIMED OUT (90 s, several times); "STORM" and "PALM" returned 0 entries; "nuclear pore" returned 19 entries, all electron tomography / FIB-SEM (EMPIAR-10162, 10155, ...). EMPIAR holds electron microscopy data; no SMLM entry was found, but the full-text search was unreliable, so this is "none found", not "none exist".
* **BioStudies / BioImage Archive** (`/biostudies/api/v1/BioImages/search`): "single-molecule localization microscopy", "SMLM raw" answered; "DNA origami" and "nuclear pore complex STORM" returned HTTP 500. Relevant hits: S-BIAD8 (the Nup96 paper's own deposit: 427 SMLM files, `.mat` localization tables of 5 to 975 MB and raw `.zip` stacks of 1 to 17 GB each, no per-frame calibration listed; not usable within the budget, the Zenodo copy of the same data is easier), S-BIAD3296 (rank 5), S-BIAD563 (ML model fitting, HTTP 500 on the record), S-BIAD3210 (spatial-spectral SMLM, not opened).
* **srm.epfl.ch**: pages of the 2013 and 2016 challenges read. 2D real: Tubulin AF647, Long Sequence, High Density (already in the repository, "ground truth unknown"), cell4; 3D real: Tubulin-A647 and NPC-A647-3D (Nup107-SNAP, Ries). No origami, no nanoruler.
* **figshare**: not queried (no API route was tried; the Zenodo and BioStudies hits covered the same papers). **bigwww.epfl.ch**: not needed.
* **ImageJ hosts** (`imagej.net`, `downloads.imagej.net`, `sites.imagej.net`) answer HTTP 200 and Java 21 is installed, so a headless ThunderSTORM run is conceivable (`sites.imagej.net/ThunderSTORM/plugins/` answers 404: the jar's location was not found; not pursued). For D1 the authors' own ThunderSTORM table is available.
* **BLOCKED (recorded, not worked around)**: `www.nature.com`, `europepmc.org`, `www.ncbi.nlm.nih.gov`, `www.biorxiv.org` (curl code 000): the papers could not be read, so every geometric constant below that is not measured in the data (NPC ring diameters, ring spacing) is from memory and must be confirmed by a reviewer who can read the papers. `api.github.com` / `raw.githubusercontent.com` refuse the repository `jungmannlab/picasso` ("GitHub access to this repository is not enabled for this session"; `add_repo` was not used), so Picasso's own sample-data documentation was not read. EBI's search endpoint is slow (above).

## Candidate records

### 1. Zenodo 3540443 (and 3539367): 2D STORM, Nup96-SNAP-Alexa Fluor 647, Thevathasan et al., Nat Methods 16, 1045 (2019)
* DOI 10.5281/zenodo.3540443, licence CC BY 4.0. "STORM, COT buffer, pxlsize 106 nm; drift correction: Au fiducials 100 nm". (File names say `Cos7_Nup96_A647_COT_Au_*` while the sister record 3539367 says U2OS Nup96-SNAP: the cell line of this record is stated inconsistently.) 3540443 has four fields of view (17, 18, 19, 20), each a Micro-Manager OME-TIFF in pieces (4.30 GB x 2 + 2.80 GB, i.e. about 30000 frames of 419 x 419 px, 378.6 kB per frame), a `*_locs.csv` (SMAP localization table of the whole recording, 55 to 72 MB) and wide-field images; 3539367 has two more fields in five pieces each (18 GB per field).
* **Ground truth**: the NPC. Nup96 sits in 8 corners of two rings (cytoplasmic and nucleoplasmic); published ring diameter about 107 nm, ring distance about 50 nm (from memory; nature.com is blocked). Measured here in the SMAP table of the frames NOT in the fetched prefix: matched-filter rings with an algebraic circle fit have a median radius of 51.0 to 51.6 nm (diameter about 103 nm, interquartile 45 to 57 nm), consistent with the literature value to within the crudeness of the finder (U). There is no per-molecule truth: labelling is incomplete and the emitters that are on in a frame are not known; the use is the geometry (radius, 8-fold phase, ring centre) of many pores.
* **Use for scoring**: NPC centres (and 8-fold phases) from the SMAP table of the frames that are not scored, localizations of the scored frames compared with the ring model (plan, section 3).
* **Raw frames and the budget**: the pieces are uncompressed multi-page TIFFs, so the first N bytes of piece 1 are a readable TIFF of whole frames. Fetched: 400,000,000 bytes (1055 whole frames, 0 to 1054) of fields 17 and 18. The table holds 50.9 k localizations in those frames (48 per frame; 41.1 per frame in frames 401 to 500) against 643 k in all 30000 frames, and the pooled reference rings have about 77 to 150 localizations each (threshold dependent) in the frames not fetched (U).
* **Acquisition metadata** (Micro-Manager block of the first frame, U): camera `PMPCIECam00`, chip `CIS2020F` (a Photometrics Prime 95B-type sCMOS; the model name is my reading of the chip name), readout 250 MHz 16 bit, ROI 962-818-419-419, `Exposure-ms` 10 and `Camera-ActualInterval-ms` 50.7 (field 17) / 50.2 (field 18), 642 nm laser setpoint 1200, camera temperature -9.8 C. **NOT in the files**: gain in e-/ADU, offset (the median frame is 323 / 317 ADU, with the table's background of about 85 photons), QE, read noise. The SMAP table holds photons (median 2302 / 2274 per localization, median CRLB of y about 6.9 nm) and background; `crlb_xnm` is corrupted (values near 8000), `crlb_ynm` is sane, `x_nm = 106 x x_pix` exactly.
* **Usability** (U): Picasso 0.11.3 default pipeline, frames 400 to 499 of field 17 with nominal camera values (baseline 100, gain 1, sensitivity 1, QE 0.95; they only change the photon column): 18.7 localizations per frame against the table's 41.1; 94.2 % of them lie within 150 nm of a table localization of the same frame, so orientation and pixel size are right. Median fitted width 135 / 132 nm (1.27 / 1.24 px). The fields are big (419 x 419 px): the ISS, which cost 7.8 s CPU per 128 x 128 frame of the 2013 tubulin set, has to be run on sub-windows (plan).
* Fields 19 and 20 and the pieces 2 to 5 (about 11 GB per field) are not fetched.
* **Feasibility rank: 1** (best structure, many pores, independent reference). Weakness: no camera calibration; the ISS noise law must be label-free as in `results/smlm/real_frc.md`; a prefix cannot be md5-checked against the full-file md5.

### 2. Zenodo 5068525: NPC SMLM data, gp210-Alexa Fluor 647, Xenopus laevis oocyte nuclear envelopes, Heil et al., Light Sci Appl 7, 99 (2018)
* DOI 10.5281/zenodo.5068525, licence CC BY 4.0, 1.5 GB in 14 files. Two experiments: STORM on glass (fetched) and mirror-enhanced STORM on a nano-mirror (not fetched, 557 MB; a different PSF and precision).
* Content of the glass experiment: `NPCData_glass_STORM.tif` 562,040,008 bytes (md5 1573237d...), **20000 raw frames of 117 x 118 px, 16 bit**, no metadata in the TIFF; the ThunderSTORM localization table (517,370 localizations, columns id, frame, x, y, sigma, intensity [photon], offset, bkgstd, chi2, uncertainty, detections; 25.9 per frame, median sigma 150 nm, median uncertainty 11.8 nm, median 939 photons) with its protocol; a wide-field image; the reconstruction, single-NPC ROI stacks, a Matlab picking script and a PDF.
* **Acquisition metadata**: pixel size 102 nm, EM gain 100, offset 100 ADU, **15.01 photoelectrons per ADU** (ThunderSTORM camera settings in `NPCData_glass_STORM_loc-protocol.txt` and the PDF), 5 ms exposure (in the original file name `..._150mW_5msexp.tif`), Alexa Fluor 647 STORM, 125 mM MEA pH 7.9. QE and frame rate not given. The ADU level is 276 ADU median, 1038 at the 99.9th percentile (U). The temporal variance of dark pixels is about 990 ADU^2 (EM excess noise).
* **Ground truth**: gp210 forms an 8-fold ring in the nuclear envelope; the rings are clearly visible in the table (hundreds of rings in one 12 x 12 um field of view). Measured in the ThunderSTORM table: median ring radius 86.4 to 87.1 nm (diameter about 173 nm, interquartile 84 to 89 nm; 157 rings at the stricter matched-filter threshold, 647 at the looser one; 470 to 570 localizations per ring over 20000 frames) (U). The published gp210 diameter was not checked (blocked). The ring is wider than the Nup96 ring and its eight-fold substructure is not resolved at about 12 nm uncertainty and antibody labelling; the geometry is therefore "a ring of radius R about 87 nm" (not a design value).
* **Usability** (U): Picasso 0.11.3 default pipeline on frames 1000 to 1199 with the real camera (gain 100, 15.01 e-/ADU, baseline 100, QE 0.9): 32.5 localizations per frame (ThunderSTORM table: 25.9), median widths 152 / 152 nm; the frames look like the reconstruction. The harness `smlm_common.run_picasso` works unchanged with `SMLM_PICASSO_PYTHON` pointing to an interpreter with `picassosr==0.11.3`.
* **Feasibility rank: 2** (one field of view only; split by pores and by frames, plan section 2; the best calibration of the three). 0.65 GB, every file verified against the md5 published by Zenodo.

### 3. Zenodo 7771932: SIMFLUX 80 nm DNA-PAINT nanorulers, Cnossen et al., Nat Methods 17, 59 (2020)
* DOI 10.5281/zenodo.7771932, licence CC BY 4.0; "Uploaded to zenodo for easy access in programming example". Three pieces of one recording (4.30, 4.30, 1.18 GB, 400 x 400 px, about 30000 frames), Hamamatsu C11440-22C (ORCA-Flash4.0 V2), exposure 10.02 ms, ROI 952-772-400-400.
* **Ground truth**: designed spacing 80 nm between docking sites of a nanoruler (title); the number of sites per ruler and their layout are not documented in the record, and the paper could not be read (blocked). DNA-PAINT: one site is on at a time, so frames are sparse; the pair-distance histogram of the localizations should show a peak at 80 nm if the pixel size is right.
* **NOT in the files**: pixel size (`PixelSizeUm` = 0; 65 nm is the natural guess for a 6.5 um sCMOS pixel and a 100x objective, but it is NOT verified; the fitted PSF of 130 nm = 2.0 px at 65 nm is consistent with it), offset (median dark level 103 ADU), e-/ADU, QE; **patterned (structured) illumination**: the excitation intensity is modulated from frame to frame, so photon counts per event vary with the pattern.
* **Usability** (U): fetched 300,000,000 bytes = 923 whole frames. Events are sparse and weak: Picasso 0.11.3 on frames 700 to 799 gives 0 localizations per frame at the default minimum net gradient 5000, 0.16 at 1500 and 7.25 at 500 (peak amplitude only about 40 to 70 ADU above 103 ADU, a few hundred photoelectrons per event; the 99.99th percentile of the pixels is 148 ADU). The same bright spots persist over many frames (a 20-frame mean shows the same spots as one frame), so ruler pairs may be unresolved doublets rather than temporally separated sites; this was not investigated.
* **Feasibility rank: 3** (the only designed-spacing origami raw frames; weakly documented; no calibration; use only as a secondary, descriptive dataset).

### 4. srm.epfl.ch, 2016 challenge, real 3D: NPC-A647-3D (Nup107-SNAP-BG-AF647 in U-2 OS, J. Ries) and Tubulin-A647-3D
* `NPC-crop-10000-frames.tif` 285,793,945 bytes (HEAD, 2026-11-09), `NPC-A647-3D-BEADS-as-stacks.tif` 21,880,088 bytes (bead z-stack, for the astigmatic calibration), full stacks of 3.6 GB each, a ThunderSTORM rendering. Same host and discipline as the repository's challenge sets (`data/smlm/fetch_real.py`). Astigmatic (cylindrical-lens) PSF: the ISS model has a circular kernel and the ring would be read in lateral position only. Not fetched.
* **Feasibility rank: 4.** A useful second NPC set only if an elliptical-PSF extension of the ISS were in scope.
