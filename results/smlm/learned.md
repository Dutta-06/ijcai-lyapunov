## Design and fairness

* Protocol, simulation, mismatch definitions and the list of what was chosen where are in the docstring of `experiments/exp_smlm_learned.py` (declared before any test-frame evaluation).
* Network: space-to-depth U-Net with widths (32, 64, 64); AdamW (weight decay 1e-4, gradient-norm clip 2; loss = BCE + 2 x Huber offsets + 0.1 x Huber log photons), learning rate 0.002 (warm-up 100 steps, cosine decay to 2 %), batch 16, 2000 steps for (a) and 1500 for (b), (c), a checkpoint every 250 steps; seeds fixed (`SEED` 20261107, the initial weights and the simulated batches per set from the set's name, so the networks of one set that differ only in the simulation's assumption share their random numbers).
* Fair comparisons: the supervised network (a) uses the development labels exactly as the E-tuned ISS and Picasso R2E+c do (checkpoint / threshold / offset on held-out or development frames, the test frames evaluated once), so (a) against ISS-E and R2E+c is the like-for-like comparison. The simulation-trained network (b) uses no label on the frames, so it is compared with the label-free rows (ISS a priori default, Picasso R0); against the tuned rows it is the comparator that has the advantage. The tuning effort differs in kind: the network has one architecture, one schedule, 11 thresholds and 8 / 6 checkpoints per model, the ISS 168 operating points, Picasso 12,000-15,000 configurations; none of them is tuned on test frames.
* Picasso under mismatch: it has no PSF, background or photon input, so its default rung R0 is constant in the sweeps; the only input of its tuned rung R2E+c that can be wrong is the width window of its post-filter, which was re-run with the window times 0.8 and 1.25 (a table in each sweep).
* The sweeps use the first 200 (LD) and first 100 (HD) test frames because the ISS is slow (and several times slower when it underestimates the noise). The ISS conditions that repeat a background mismatch with the slope recomputed (`a / factor`) were run on the LD set only.
* Not comparable with the CNN's numbers: DECODE's published leaderboard results (3D only, hidden test sets).
* The MT0 sets are simulated and share one structure (three microtubules): the development and test frames are not independent datasets. A network trained with flips and rotations on frames cannot memorise the absolute position of the microtubules, but it may learn their local shape; the simulation-trained network has seen no microtubule at all.
* Limits of the evidence: one network per cell (a single seed; the jumps of the validation E between neighbouring checkpoints in the training-curve tables, up to about 6 points for the supervised networks on 200 held-out frames, measure the noise of the choice of checkpoint and threshold); the supervised network trains on 80 % of the development frames (the ISS and Picasso are tuned on all of them; the labelled-data table shows what fewer frames cost); one architecture and a handful of pilot comparisons, no hyper-parameter search; the mismatch sweep changes one assumption at a time; the simulation of (b) has no axial dependence beyond the width spread, no long halo and uniform emitter positions (the real emitters lie on three microtubules); the frames of one set are not independent samples of the structure; the Picasso seconds per frame are those stored by `exp_smlm_iss.py --only P` (a wall-clock on a shared machine).
* Reproduce: `python experiments/exp_smlm_learned.py --run` (needs torch, `SMLM_PICASSO_PYTHON` for the Picasso window stage, `LEARNED_WEIGHTS` outside the repository; stages train / infer / iss / picasso / collect, resumable, workers share a queue; the weights and caches are not part of the repository) writes `learned_raw.npz`; `python experiments/exp_smlm_learned.py --from-raw` regenerates this file from it byte for byte (numpy and scipy only). Tests: `tests/test_learned_localizer.py` (the torch tests need torch).
