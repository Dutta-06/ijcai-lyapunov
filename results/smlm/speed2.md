# The cost of the ISS frame fit: the original evaluation, the fast evaluation of the same algorithm, and Picasso

Generated by `experiments/exp_speed2.py` from `speed2_raw.npz`; every number below is printed by the script. Declared in `speed2_plan.md` (committed before the runs). Development frames and development patches only. One process, one thread, a machine shared with other jobs: the seconds are the minimum over interleaved repeats of the PROCESS CPU time (the wall time is in the raw), so they are the cost with the least interference, not a benchmark of an idle machine. "old" = `exp_smlm_iss.run_frame` (`imaging.sliding_path`, `imaging.refine`, scipy `least_squares`), "new" = `smlm_fast.run_frame_fast` (`imaging_fast`), "new, no early exit" = the same without the exit at the first entrant below the significance threshold.

Platform: Intel(R) Xeon(R) Processor @ 2.30GHz, 4 cores; 1-minute load average sampled every 30 s during the timing parts (89 samples): minimum 5.4, median 7.0, maximum 14.8. The machine was shared with other jobs throughout, so absolute seconds are inflated and noisy; every ratio below compares engines measured interleaved in the same session on this one machine (never across machines).

Intervals: 95 % percentile bootstrap over the frames (1000 resamples, seed 0) of the ratio of the sums over frames. Picasso: rung R2E of the ladder (`picasso_ladder_raw.npz`, options per set), identification and fit of one frame at a time after a JIT warm-up, Picasso 0.11.3, the same CPU-time minimum over 3 repeats.

**Pooled over the four sets (mean of the sets' means):** old 0.9725 s / frame, new 0.0796 s / frame, Picasso 0.00209 s / frame: old / new = 12.2, new / Picasso = 38, old / Picasso = 465.

**Three cost bands against Picasso** (per set: ratio of the sums over the 24 frames; pooled: ratio of the means of the sets' mean seconds, with a 95 % percentile interval of a frame bootstrap within each set, 1000 resamples, seed 0, the same frame draw for every engine): the new evaluation with its early exit at one fixed threshold is 5-98x slower than Picasso per set (pooled 38 [30, 47]); the new evaluation without the early exit (the whole path kept) is 55-175x per set (pooled 106 [92, 123]); the original is 201-837x per set (pooled 465 [383, 562]). Only the first band is the cost of a single fixed threshold; the other two are the cost of the path.

**What the speed-up consists of.** The pooled old / new = 12.2 [10.9, 13.8] mixes two effects: the exact arithmetic alone (old / new without the early exit) is 3.6-4.8x per set, and the rest is the early exit (1.8-11.8x per set), which exists only for a single fixed `snr` threshold and is off for any other rule or for a kept path. Per set old / new is 9-43x. The plan states "at least 10x" for a set only if the lower end of its interval is >= 10: this does not hold for MT0.N1.HD (lower end 7.7), which does not reach the plan's own 10x rule. The pooled lower end is 10.9 (at least 10).

**The limit-cycle guard never triggered on real data.** The SMLM engines run with `cycle_guard` off (as the originals do), and on the astronomy patches the barred set was empty for both engines on the complete paths in the referee's rerun (the raw stores only whether the two barred lists agree, not whether they are empty, so "barred set identical" in section 4 is vacuous on real data). The equivalence of the guard is tested on planted cycles only (`tests/test_imaging_fast.py`).
