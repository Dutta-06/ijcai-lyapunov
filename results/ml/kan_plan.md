# Plan (pre-registration): does the factorised small-start Gaussian readout select the number of units in a Kolmogorov-Arnold network?

Written 2026-11-09 18:12 UTC (first commit ec79f56), before any test target or test set was scored (by then only the OpenML dataset listing and the sets the selection rule yields had been looked at, with names, sizes and checksums, no target values scored; later development work is in the Amendments). The plan is committed before the test run; later changes are listed under *Amendments* with their UTC time. Code:
`experiments/exp_kan_spike.py`; tests: `tests/test_exp_kan_spike.py`. This is a SPIKE: small networks, few seeds, one frozen configuration per method.

## Question
The theory (proved in 1-D, with fixed widths) says that gradient flow of a Gaussian-unit network with a factorised readout `w = nu^2 * A * tanh(alpha/A)`,
`alpha(0) = 0`, `nu(0)^2 = eps` small, switches units on one at a time, slides them onto features and leaves the unneeded ones dormant: the number of units is
chosen by training. A KAN edge is a learnable 1-D function, often a sum of Gaussian RBF units (FastKAN), whose grid size is a hyper-parameter and whose pruning is a
known weak point. Primary question: **at equal active parameters the factorised KAN is non-inferior to the best baseline, and it recovers the true number of units per
edge better than the same network trained the standard way with an L1 penalty and magnitude pruning, with no grid size to set.**

## Models (all in torch, CPU, full batch, 0.5 * MSE, early stopping on a validation split, the iterate of lowest validation MSE is kept)
* **ours** (`fact`): every edge is `sum_k w_k exp(-(x-c_k)^2/(2 s_k^2))`, `M = 10` initial units, centres initially on a uniform grid of `[-2.5, 2.5]`, widths initially
  the grid spacing, all of `c, s` (log-parametrised, clamped to `[0.05, 3]`) learnable; `w = nu^2 A tanh(alpha/A)`, `A = 3`, `alpha(0) = 0`, `nu(0)^2 = eps`. Variants
  `gd` (plain gradient descent, per-group rates: the paper's flow) and `adam`; the variant, `eps` and the rates are chosen on development data (grid in the code, `DEV_GRID`).
* **control** (`free`, the key control): the same units, `w` direct with standard initialisation `N(0, 0.1^2)`, Adam, an L1 penalty `lambda * sum|w|` with
  `lambda in {0, 3e-4, 1e-3, 3e-3, 1e-2}`, then magnitude pruning (units below the activity rule are removed) and a 600-step fine-tune. The penalty is chosen **per run by validation
  (one-standard-error rule: the fewest active parameters among penalties whose validation MSE is within `1 + sqrt(2/n_val)` of the best)**; the penalty chosen by the truth
  (oracle, most generous to the control) is reported as well.
* **fixed grid** (FastKAN-style): `G` centres on a uniform grid, width = spacing, only `w` trained, `G in {2, 3, 4, 6, 8, 12}`; **MLP**: two hidden layers of width `h in {2,3,4,6,8,12,16,24}`, SiLU.
* No base (linear/SiLU) path is added to any KAN: the edges are pure Gaussian sums, equally for all KAN variants. Hidden pre-activations of a two-layer KAN are standardised
  with the (detached) training-batch statistics (standard deviation floored at 0.05) before the next layer, equally for all KAN variants. Inputs of real sets: quantile-normal transform fitted on
  the training rows, clipped at +-4; targets standardised.
* Every baseline gets the same tuning effort as ours: ours has 8 configurations on the development data, each baseline family 2-3 learning rates (and its capacity axis
  `lambda` / `G` / `h` is part of the curve, run at test); the learning rates of the baselines are chosen on the development data by lowest mean validation MSE. The chosen
  configuration of every method is frozen in `results/ml/kan_freeze.json`, committed before the test run.

## Activity rule and active parameters (the same for every KAN)
A unit is **active** when its root-mean-square contribution on (up to 2000) training inputs is at least `tau = 0.02` times the standard deviation of its output node's
pre-activation. Counts are also reported at `tau = 0.01` and `0.05`. Active parameters: 3 per active unit (`w, c, s`; 1 for a fixed grid), plus 1 bias per node; for the MLP all parameters.

## Benchmarks (fixed before scoring)
(a) **SYNTH, model-order test**: 10 test targets (ids 1-10) and 3 development targets (ids 101-103) generated by `make_target`: additive `sum_{i=1..5} g_i(x_i)`, `g_i` a sum of
`K_i in {0..4}` Gaussian bumps (centres in `[-1.8, 1.8]` at least 1 apart, widths 0.25-0.45, signed amplitudes 0.8-1.5; at least one irrelevant input with `K = 0`, at least one edge with `K >= 3`,
`6 <= sum K <= 11`), unit variance, inputs `U(-2.5, 2.5)`, noise sd 0.1 and 0.4, 3 seeds (development: seeds 0, 1), 1500 train / 500 validation noisy rows, 2000 clean test rows; network `[5, 1]` (each edge an input; the true count per edge is `K_i`).
(b) **REAL**: OpenML regression sets by `select_real` (listing filter: active, 1000-20000 rows, 6-31 features including the target, no missing values; ascending id; numeric only; first of each
name; names starting `fri_` and `kin8nm, puma8NH, bank8FM` (Delve simulations), `cpu_small` (subset of `cpu_act`), `Titanic` (a class-label task whose default target is numeric) dropped; target with at least 50 distinct finite values;
the first 11 qualifying sets, ranks 3, 6, 9 are development, the other 8 are test). The sets, ids and checksums are recorded in `results/ml/kan_sets.json` (raw data are not committed). Rows above 4000 are
subsampled (fixed seed; see Amendment 1); splits 60/20/20, 3 split seeds per set (development: 1). Primary architecture `[d, 4, 1]`; secondary `[d, 1]`.

## Metrics
Test RMSE (real: standardised target; synth: against the clean function) against active parameters; active units per edge against the truth (synthetic); stability over seeds
(sd of RMSE, coefficient of variation of active parameters, sd of the exact-edge share); training time.

## Decision rule (the single primary verdict)
* **S (model order)**: per run the share of the 5 edges whose active-unit count equals `K_i` is computed for ours and for the control with the validation-chosen penalty. The gain
  (ours minus control) is averaged over noise levels and seeds within each of the 10 test targets and the 10 target means are bootstrapped (10,000 cluster resamples, percentile 95% interval). **S is met if
  the gain is at least 0.10 and its 95% interval excludes 0.**
* **R (accuracy)**: per real test set, per split seed, ours (one model, with `P` active parameters) is compared with the best member, over the three baseline families, that uses at most `P` active
  parameters (a family whose smallest member is larger is compared with that member and flagged); the mean log ratio of test RMSEs over the three splits must be at most `log 1.05`
  (non-inferior; below `log 0.95` a win, above `log 1.05` a loss). The best baseline is picked on the test RMSE (an oracle choice, favouring the baselines). **R is met if ours is non-inferior on at least 6 of the 8 test sets.**
* **GO if S and R are both met; KILL otherwise.** The verdict is computed by `verdict()` and printed in `results/ml/kan.md`.
* If KILL, the cause is read from the same raw data and reported: (i) the control equals ours on counts (gain interval contains 0): "penalised control equal"; (ii) ours is worse than or equal to
  a fixed-grid or the control on accuracy only: accuracy failure; (iii) `gd` against `adam` on development (does Adam's per-parameter normalisation erase the small-start dormancy: units of unneeded edges become active) ;
  (iv) `[d, 1]` against `[d, 4, 1]` on the real sets (coupled edges); (v) whether the units found sit at the true centres.

## Development / freeze / test
Everything is chosen on development data only: ours (variant, `eps`, rate) by the highest mean exact-edge share on the development targets among the configurations whose development-set test RMSE is within a
factor 1.15 of the best baseline member (else the lowest ratio); baseline learning rates by validation MSE. Then `kan_freeze.json` is written and committed, and the test run is made once. Anything done
after seeing the test results is labelled POST HOC. The control's penalty grid, the grids `G`, `h`, the activity rule and the margins above are fixed here and are not tuned.

## What will be dropped
Nothing is dropped after scoring: failed or diverged runs stay in the raw data (a model that never leaves its dormant start is an honest failure of that method and counts as such). Optional comparators not included in the spike:
EfficientKAN (B-splines), base-path variants, a learned two-layer count truth. A synthetic compositional (non-additive) panel is not part of this spike.
